# 실습 프로젝트 개선 기록

이 문서는 원본 학습 예제와 이번 정리 작업을 구분하고, 변경 이유와 확인한 동작을 기록합니다. 구직용 설명에서 구현 범위를 과장하지 않기 위한 근거 문서입니다.

## 출발점

- 원본: 2023년 12월 27일 작성한 3개 커밋
- 기준 커밋: `7ca44a6`
- 구성: HTTP 메서드, 요청 바인딩, HTML·JSON 응답, Jackson 변환 예제
- 부족했던 부분: README, 실행 화면 안내, 입력 검증, 자동 검증 중심 테스트

기존 `com.sparta.springmvc` 패키지와 주요 실습 URL을 유지했습니다. 학습 예제에서 출발한 프로젝트이며, 상용 서비스나 DB 기반 CRUD를 구현했다고 설명하지 않습니다.

## 변경 내용과 판단

| 문제 | 개선 | 판단 근거 |
|---|---|---|
| 예제의 목적을 저장소 첫 화면에서 알기 어려움 | 구직용 README, 실행 화면, 실습 가이드 추가 | 구현 범위와 검증 방법을 바로 확인하도록 구성 |
| 요청 바인딩 결과가 HTML 포함 문자열 | 바인딩 방식·이름·나이를 JSON으로 응답 | 데이터 전달과 화면 표현의 책임을 구분 |
| 문자열·객체 응답의 차이가 주석에 의존 | Content-Type 명시와 비교 화면 추가 | 실제 응답 헤더로 차이를 확인 |
| 잘못된 입력을 기본 오류에 맡김 | Jakarta Validation과 공통 오류 응답 | 누락·범위·타입 오류를 클라이언트에서 처리 가능 |
| 응답 문자열을 innerHTML에 삽입 | textContent 출력 | 입력이 HTML·이벤트 코드로 해석되지 않도록 처리 |
| 비원자적 공유 카운터 증가 | 인스턴스의 AtomicLong 사용 | 동시 요청 누락을 방지하되 영속화는 별도 범위로 유지 |
| API를 실행하려면 별도 도구가 필요 | Swagger UI와 웹 실습 도구 추가 | 명세와 실제 응답을 같은 서버에서 비교 |
| 폼 객체 요청이 OpenAPI에서 쿼리로 표현됨 | 폼 요청 본문 스키마를 명시 | 문서에서 실제 form-urlencoded 요청이 전송되도록 수정 |
| 결과 출력만 하던 테스트 | 값·상태·헤더·오류를 검증하는 테스트 | 회귀를 자동으로 발견하도록 개선 |
| 환경과 변경 후 검증 방법이 불명확 | Java·Gradle 정비, CI 추가 | 실행과 테스트 과정을 재현 가능하게 구성 |

Java 17을 유지하고 Spring Boot 3.1.0에서 3.5.16으로 정비했습니다. 원본과 같은 MVC·Jackson 2 기반 학습 구조를 유지하는 선택이며, 최신 메이저 버전으로 이전하는 프로젝트는 아닙니다.

## 검증 근거

정리 작업 중 서버 테스트 40개와 실행 JAR 빌드를 통과했습니다. 정적인 소스 검토에 더해 실제 서버와 브라우저를 연결했습니다.

| 영역 | 확인한 동작 |
|---|---|
| 요청 | 바인딩 6종과 HTTP 메서드별 라우팅 |
| 검증 | 이름 길이·공백, 나이 0·150 경계, 누락·잘못된 타입·JSON 문법 |
| 응답 | 문자열·객체의 Content-Type, 공통 오류 코드 |
| 화면 | 정상·오류 입력, 안전한 텍스트 출력, 모바일·키보드 |
| 비동기 | 로딩, 중복 전송 방지, 연결 실패 후 재시도, 시간 초과 안내 |
| HTML | 정적·템플릿·동적 응답과 리다이렉트 |
| API 문서 | OpenAPI 요청 본문 형식, Swagger UI에서 JSON·폼 실제 전송 |
| 동시성 | 8개 스레드의 200회 증가 결과에 누락·중복 없음 |

웹 화면 캡처는 [images](images/)에서 확인할 수 있습니다. 자동화된 브라우저 검증은 `scripts/browser-smoke.mjs`에 보관했습니다. 화면 정적 검사는 색상 토큰 일치, 레이블, 상태 안내, 안전한 출력 방식을 확인합니다. 이 검사가 모든 접근성 기준 준수를 보증하지는 않습니다.

GitHub Actions에는 서버·브라우저 검증과 결과 아티팩트 업로드를 구성했습니다. 개별 실행 성공 여부는 저장소의 Actions 결과를 기준으로 확인합니다.

## 구직 자료에서 설명할 범위

> 프론트엔드에서 전달한 경로·쿼리·폼·JSON 데이터를 Spring MVC가 처리하는 과정을 비교하는 학습 프로젝트입니다. 기존 예제를 실행 가능한 웹 도구와 Swagger UI로 정리하고, 입력 검증·공통 오류 응답·자동화 테스트를 보완했습니다.

설명할 수 있는 역량은 요청·응답 계약 이해, 입력 검증, 오류 처리, API 문서와 구현의 일치, 화면과 서버를 연결한 검증입니다. 실제 사용자 운영, 성능 개선 수치, DB·인증 설계, CRUD 구현 경험으로 확대해서 설명하지 않습니다.
